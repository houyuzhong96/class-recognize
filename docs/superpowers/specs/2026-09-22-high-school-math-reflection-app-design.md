# 高中数学教学反思记录应用设计说明

## 1. 背景

用户需要一款界面简洁的小软件，用于长期记录高中数学每节课的教学反思、教学总结、学生易错点等内容。记录需要按教材、章节和课次组织，并能在电脑端和手机端随时查阅、补充和更新。

首版教材预设为人教A版（2019年版）高中数学，包括必修第一册、必修第二册、选择性必修第一册、选择性必修第二册和选择性必修第三册。章节目录允许后续维护，不把用户限制在固定预设中。

## 2. 目标

### 2.1 核心目标

1. 按教材、章、节浏览高中数学课程结构。
2. 针对每节课记录教学反思、教学总结和学生易错点。
3. 支持按关键词、章节和日期查找历史记录，并继续补充或修改。
4. 电脑端和手机端登录同一账号，查看和更新同一份云端数据。
5. 在手机端提供接近原生应用的 PWA 使用体验。
6. 允许导出数据，避免用户数据被锁定在应用内。

### 2.2 首版不包含

1. 多人协作编辑或教师团队共享。
2. 自动生成教学分析、AI 总结或成绩分析。
3. 扫描纸面材料、拍照 OCR 和附件管理。
4. 以 GitHub 仓库作为主数据库或实时同步通道。
5. 复杂的学习计划、学生管理和学校教务系统集成。

## 3. 用户与场景

首版面向单一的教师个人账号。

典型场景：

1. 下课后在手机上选择教材章节，新建本节课记录。
2. 在电脑上搜索某个易错点，找到历史课次并补充改进措施。
3. 备课前按章节查看过去记录，快速回顾学生问题和教学处理方式。
4. 在无网络环境下继续编辑，恢复网络后自动同步；如果同步失败，草稿仍保留在本机。
5. 定期导出 JSON 或 Markdown，作为独立备份。

## 4. 技术方案

### 4.1 采用方案

- 前端：React、TypeScript、Vite。
- 应用形态：响应式 PWA。
- 认证与数据库：Supabase Auth 和 PostgreSQL。
- 权限：Supabase Row Level Security，按登录用户隔离数据。
- 部署：Vercel。
- 源码与版本管理：GitHub。
- 测试：Vitest、React Testing Library 和 Playwright。

### 4.2 GitHub 的定位

GitHub 用于保存源代码和设计文档，不承担应用主数据同步。

原因：

1. 手机和电脑频繁提交文件时容易产生 Git 冲突。
2. GitHub 不适合为普通业务记录提供细粒度权限和逐条更新。
3. 在客户端调用 GitHub API 需要管理访问令牌，安全风险更高。
4. 离线合并、删除和并发编辑无法像数据库一样可靠处理。

首版使用 Supabase 作为数据中转站，提供 JSON 和 Markdown 导出。后续如有必要，可增加“手动或定时把导出快照提交到私有 GitHub 仓库”的备份功能，但不把它作为实时同步机制。

## 5. 信息架构

### 5.1 层级

教材 -> 章 -> 节 -> 课次记录

### 5.2 首版预设

首版初始化人教A版（2019年版）教材目录：

- 必修第一册
- 必修第二册
- 选择性必修第一册
- 选择性必修第二册
- 选择性必修第三册

章、节数据存储在数据库中，用户可后续增加、修改或隐藏目录项。用户记录始终关联到具体的节；如需记录整章总结，可以创建一个特殊记录并标注为“章末总结”。

## 6. 数据模型

### 6.1 `profiles`

保存用户显示信息。

- `id`：与 Supabase Auth 用户一致。
- `display_name`：显示名称。
- `created_at`、`updated_at`：创建和更新时间。

### 6.2 `textbooks`

保存教材。

- `id`
- `owner_id`：所属用户。
- `name`：例如“必修第一册”。
- `edition`：例如“人教A版2019”。
- `display_order`
- `is_archived`
- `created_at`、`updated_at`

### 6.3 `chapters`

保存章。

- `id`
- `owner_id`
- `textbook_id`
- `name`
- `display_order`
- `is_archived`
- `created_at`、`updated_at`

### 6.4 `sections`

保存节。

- `id`
- `owner_id`
- `chapter_id`
- `name`
- `display_order`
- `is_archived`
- `created_at`、`updated_at`

### 6.5 `lesson_records`

保存每节课的记录。

- `id`
- `owner_id`
- `section_id`
- `lesson_date`
- `lesson_type`：新授课、习题课、复习课、讲评课或其他。
- `title`：可选课次标题。
- `teaching_reflection`：教学反思。
- `teaching_summary`：教学总结。
- `student_mistakes`：学生易错点。
- `improvement_actions`：改进措施。
- `tags`：文本数组。
- `version`：用于并发更新检测。
- `is_archived`
- `created_at`、`updated_at`

### 6.6 `record_revisions`

保存最近版本，降低误编辑和同步冲突造成的内容损失。

- `id`
- `record_id`
- `owner_id`
- `snapshot`：变更前的数据快照。
- `created_at`

## 7. 页面与交互

### 7.1 目录页

- 展示教材、章、节三级目录。
- 节项显示已有记录数量。
- 支持展开、收起和快速新增记录。
- 首页展示最近编辑记录和当前正在教学的章节。

### 7.2 章节记录页

- 按日期倒序显示该节下的记录。
- 每条记录显示日期、课型、教学总结摘要和易错点摘要。
- 支持新增、编辑、归档和恢复。

### 7.3 记录编辑器

字段包括：

- 日期
- 课型
- 可选标题
- 教学反思
- 教学总结
- 学生易错点
- 改进措施
- 标签

编辑体验：

1. 输入后本地立即保存草稿。
2. 稳定停顿后自动同步云端。
3. 顶部持续显示“保存中、已保存、等待联网或保存失败”。
4. 同步失败时允许重试，不丢失本机内容。
5. 离开页面前只对无法保存的草稿进行明确提示。

### 7.4 搜索页

- 支持全文关键词搜索。
- 支持教材、章、节和日期范围筛选。
- 支持按最近修改、上课日期排序。
- 搜索结果直接打开对应记录，并保留返回搜索条件的路径。

### 7.5 设置页

- 当前账号信息。
- 云端同步状态。
- 导出全部数据为 JSON。
- 导出全部数据为 Markdown。
- 退出登录。
- 查看已归档记录并恢复。

### 7.6 响应式布局

电脑端：

- 左侧教材目录。
- 中间记录列表。
- 右侧编辑器或记录详情。

手机端：

- 底部导航包含“目录、搜索、归档、设置”。
- 目录、章节列表和记录详情采用单列页面。
- 编辑器使用适合触屏的大输入区域和固定底部操作栏。

## 8. 视觉方向

1. 整体采用白色、浅灰和深色正文，蓝色作为主要操作色。
2. 易错点使用少量橙红色强调，但不大面积使用高饱和背景。
3. 图标使用 Lucide 图标库，避免只有文字的长按钮。
4. 电脑端强调信息密度和键盘效率；手机端强调单手操作和清晰层级。
5. 不使用营销式首页，打开应用后直接进入记录工作区。
6. 卡片只用于重复的记录项、模态框和独立工具，不嵌套卡片。

## 9. 数据流与同步

1. 用户登录后获取账号资料、教材目录和记录。
2. 目录数据优先从本地缓存读取，再在后台刷新。
3. 编辑器更新先写入本地状态和 IndexedDB 草稿队列。
4. 前台稳定后执行 Supabase upsert 操作。
5. 更新携带 `version`，数据库仅接受预期版本并递增版本号。
6. 版本冲突时提示用户比较本机版本和云端版本，不静默覆盖。
7. 网络恢复后按记录时间顺序重放未同步草稿。
8. 同步成功后清理草稿队列并更新界面状态。

## 10. 错误处理

1. 登录失效：保留未同步草稿，提示重新登录。
2. 网络中断：允许继续编辑，显示离线状态。
3. 云端失败：提供重试，并保留本机草稿。
4. 并发冲突：显示两个版本的时间和内容差异，由用户决定保留哪一版。
5. 删除操作：默认归档而不是物理删除；恢复入口清晰可见。
6. 导入导出异常：导出前校验数据完整性，失败时给出可操作的错误信息。

## 11. 安全与隐私

1. 所有业务表启用 Row Level Security。
2. 用户只能读取和修改 `owner_id` 等于自己的数据。
3. 不在浏览器本地保存 Supabase 服务角色密钥。
4. 生产环境只使用公开的匿名密钥和用户会话。
5. 导出的文件由用户自行保管，不自动上传到第三方。

## 12. 测试与验收

### 12.1 自动化测试

- 单元测试：数据转换、搜索过滤、Markdown 导出和同步状态机。
- 组件测试：目录树、记录表单、空状态、错误状态和归档恢复。
- 端到端测试：登录、新建记录、编辑、搜索、刷新后仍存在、导出、手机视口操作。
- 数据库测试：验证 RLS 隔离和版本冲突处理。

### 12.2 验收标准

1. 用户可以在人教A版2019教材下按章、节浏览。
2. 用户可以新建并编辑一节课的全部记录字段。
3. 电脑端和手机端登录同一账号后能看到相同数据。
4. 刷新页面或重新登录后，已同步记录仍然存在。
5. 无网络时编辑内容不会丢失，恢复网络后可以同步。
6. 可以按关键词、章节和日期找到记录。
7. 可以归档、恢复并导出全部记录。
8. 桌面和手机视口均无横向溢出、控件重叠或不可操作区域。
9. 主要页面可以离线打开，离线状态有明确反馈。

## 13. 交付顺序

1. 初始化 React、TypeScript、Vite 和 PWA 工程。
2. 建立 Supabase 数据表、RLS 策略和人教A版2019目录种子数据。
3. 实现登录、应用外壳和响应式导航。
4. 实现目录浏览、章节记录列表和记录编辑器。
5. 实现本地草稿、云端同步、错误恢复和版本冲突处理。
6. 实现搜索、归档、恢复及 JSON/Markdown 导出。
7. 补充自动化测试和桌面、手机端浏览器验证。
8. 编写部署与环境配置说明，并在 Vercel 部署。
